# 三态判定与多源校验

> 一句话：**`idle` 只表示"没有运动"，不等于"房间无人"。**
> 只有 CSI 无运动 + ≥2 路旁证一致 + 持续超过阈值，才输出 `empty_confident`；
> 判不准就输出 `uncertain`，节点掉线输出 `degraded`。

## 一、四个值（三态判定，四值实现）

| 值 | 触发条件 | 允许的下游动作 |
|---|---|---|
| `present_confident` | 任一新鲜节点处于 `motion` | 可逆动作 |
| `empty_confident` | 全部节点 idle ≥ 阈值，且旁证 ≥2 路一致 | 可逆动作（关灯/关空调/扫地机进入） |
| `uncertain` | 数据不足、节点冲突、旁证矛盾、旁证不够 | **不执行关灯/关空调**，只出询问式建议 |
| `degraded` | 依赖节点达到离线超时 | 只下调置信度并告警，**禁止推断无人** |

## 二、两条不能违反的规则

### 1. `idle` ≠ `empty`

`fuse_rooms()` 在全部节点 idle 超过 `empty_requires_all_nodes_idle_seconds`（默认 300s）
时只置 `empty_candidate=True`，状态仍是 `uncertain`。原因：

- 人静坐时 CSI 微动幅度与链路漂移同量级；
- 宠物、风扇、窗帘、镜面反射都会制造"幽灵运动/静止"；
- 只凭 CSI 判无人 → 误关空调/照明，是同类方案最常见的过度承诺。

### 2. 单源不得判无人

`corroborate()` 要求至少 `min_sources`（默认 2）路旁证一致指向无人。
少于 2 路 → `uncertain`（"不确定"是正确输出，不是系统故障）。

## 三、六路旁证

| # | 源 | 无人的证据 | 有人的证据 | 当前状态 |
|---|---|---|---|---|
| 1 | CSI | 全部节点 idle ≥ 阈值 | 任一节点 motion | 真实（接 ESPectre） |
| 2 | PIR | 窗口内无较大动作 | 窗口内有动作 | 仿真 `pir_*` |
| 3 | 插座功率 | 低于阈值（如 <20W） | 高于阈值 | 仿真 `plug_power_*` |
| 4 | 设备操作 | 窗口内该房间无操作 | 有操作 | 真实（审计日志） |
| 5 | 作息基线 | 该时段历史上通常无人 | 通常有人 | 配置仿真 `routine` |
| 6 | 门磁 | 窗口内未开门 | 开过门 | 仿真 `door_entry_open` |

> 除 CSI 与"设备操作"外，其余在证据里标 `source_kind="simulated"`。
> 接真实器件时只换 `RoomService._collect_evidence()` 的取值来源，判定规则不变。

## 四、判定流程

```text
NodeRegistry.states(now)
   └─► fuse_rooms()                       # 只回答"有没有运动"
         ├─ motion           → present_confident
         ├─ 无新鲜节点        → degraded（不推断无人）
         └─ 全部 idle ≥ 阈值  → uncertain + empty_candidate=True
                 └─► corroborate()         # 回答"旁证是否一致"
                       ├─ 任一源指向有人 → uncertain + 冲突类别
                       ├─ 一致源 ≥ min   → empty_confident
                       └─ 一致源不足     → uncertain（旁证不足）
```

冲突分类（`corroborate()`）：

| 类别 | 典型组合 |
|---|---|
| `human` | PIR 有动作 + 插座功率高（或近期有设备操作） |
| `pet` | PIR 有动作 + 无用电 + 无操作；或门刚开过但无其它活动 |
| `environment` | 仅插座功率高（电器在跑），PIR 无动作 |
| `fault` | 传感器读数缺失/自相矛盾（预留） |
| `unknown` | 有冲突但无法归入以上 |

## 五、节点冲突与掉线

- **节点间冲突**（一个 motion、一个 idle）：保留 motion 作为活动证据，
  记录节点分歧，房间不因单个 idle 转无人；
- **节点掉线**：`stale` 只由 `last_event_at` 判定，health 心跳**不能**续命；
  达到离线超时 → `degraded`，只告警不推断；
- 房间状态变化只在**状态类别**改变时产生事件（冷却去重），
  `uncertain` 永不产生 `no_person`。

```json

    "empty_requires_min_corroborating_sources": 2,
    "degraded_on_node_stale": true,
    "motion_overrides_idle": true,
    "uncertain_on_conflict": true

  "corroboration": {

             "degraded_event": "room_degraded", "cooldown_seconds": 120}
}
```

## 七、接口

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/rooms` | 四态 + 置信度 + 证据来源 + 节点在线 |
| GET | `/api/rooms/{room_id}/timeline` | 状态变化时间线（只在变化时追加） |
| POST | `/api/rooms/tick` | 手动推进一轮（演示） |
| GET | `/api/csi/status` | enabled / paho / MQTT 连接 / 节点统计 |
| POST | `/api/csi/replay` | 回放节点事件（无硬件演示） |

## 八、验收判据（目标，未实测前不填数字）

- 空房间每小时误报 ≤ 2 次；
- 静坐（30 分钟）漏报 ≤ 20%；
- 节点掉线后**不产生错误的无人判定**；
- `uncertain` 状态下不执行关空调/关灯（由 `tests_csi.py` 与事件路由共同守门）。

## 九、测试

`python tests_csi.py`（104 项）覆盖：

- motion 契约、`idle ≠ empty`、299s/302s 边界；
- `sweep()` 超时 → `degraded`、离线不判无人；
- 节点冲突 → `uncertain`；
- 六路旁证：单源不足、4 路一致 → empty、human/pet/environment 归因；
- `to_dict()` 不含原始 CSI；
- `ingest/`、`rooms.py` 无设备动作调用（AST）。
