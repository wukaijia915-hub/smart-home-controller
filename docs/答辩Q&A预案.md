# 答辩 Q&A 预案

> **用法**：每一条给出「一句话答 → 展开 → 证据位置 → **不要说的话**」。
> 最后一项往往最有用 —— 答辩的失分多数不是答不上来，而是**多说了一句本可以不说的话**，
> 把自己送到评委的追问方向上。
>
> 一条总原则：**主动暴露边界 = 可信度。** 本项目所有"未达标""未标定""未实测"
> 都已经写进文档，评委问到时直接承认并给出理由，比含糊其辞强得多。

## 一、最高频的三个问题

### Q1. 这和直接用 LangChain Agent 有什么区别？

**一句话答**：「护栏在架构里，不在 prompt 里；而且我们**实测否决**了自己写的 ReAct 循环。」

**展开**：
1. Root 的工具视图**全部只读**，每个副作用动作强制走租约链 —— 模型选错设备的结果是
   **被拒绝**，不是**被执行**。
2. 证据链与可测性：回读三态证据、租约状态机、五级漏斗顺序，**每一条都有对应测试**；
   通用状态图很难对"框架应该怎么流转"写断言。
3. 6 行 requirements 是"pip install 即跑、浏览器打开就能演示"卖点的一部分。

**证据**：`docs/为什么不用LangChain.md`（全文）、`backend/gate.py`、`tests_funnel.py`

**不要说**：「LangChain 太重/不好用」—— 这是主观评价，且评委可能就喜欢它。
说**"它解决的问题不是我们的瓶颈，而它带来的故障面落在我们最不想出问题的地方"**。

---

### Q2. 你们有心镜的心理健康背景，为什么不做情绪测量？

**一句话答**：「**本项目不做情绪测量。** 非接触式情绪识别在公开验证中 ICC 多为负值，
我们不引入未经充分验证的测量手段**作为控制回路的输入**。我们接入它，
但用模态一致性检验管住它，并如实报告它的边界。」

**展开（如果评委继续问）**：
- 心镜自己的评测数据：14 个参数修复后仅 **2/14** ANOVA 显著；稳定性 ICC 多为**负值**
  （aggression −0.47、charm −0.39）；微运动特征对效价 **r = 0.021**（≈ 无信号），
  而内容基线 r = 0.692。
- ICC 为负值表示**测量结果比随机猜测还差**。
- 所以我们的处理是"**引入信号 → 用交叉验证管住它 → 如实报告边界**"。
- 值得一说的是：**多模态一致性检验这个机制，心镜自己的融合模块里已经有了，
  但它没有用它来管住 VibraImage。** 我们把这两块接起来。

**证据**：`docs/感知层可靠性报告.md` §四

**不要说**：「我们做过情绪识别但效果一般」。这会把话题引到"你们做失败了"，
而正确的表述是"**我们有意识地不把它当成测量工具**"——这是主动的设计决定，不是失败的退路。

---

### Q3. 你们的感知层准确率是多少？

**一句话答**：「**这个问题我们不给数字，因为给不出有依据的数字。** 我们报告的是一条
**可靠性链**，而不是一个准确率。」

**展开**：逐路说明（这段建议背下来，是本节的核心）：

| 模态 | 数据来源 | 能否给准确率 |
|---|---|---|
| 环境行为 | **真实**传感器读数 + 真实操作日志 | 可给（但它是确定性的，不需要"准确率"） |
| 视觉行为 | ⚠️ **关键词模拟**（软件阶段） | **不能** —— 当前价值在验证融合机制 |
| 面部表情 | 演示级，公开 FER 基准 ~65–70% | **不做承诺** |
| 前庭振动 | 上游已证伪（见 Q2） | **不能** |

**能保证的是**：单模态误判不会穿透到下游 —— 模态间矛盾时整组结果被丢弃；
零信息时**不给建议而不是给 0.5**；感知层在架构上**没有执行设备的能力**（静态扫描强制）。

**证据**：`docs/感知层可靠性报告.md`

**不要说**：「准确率 85%」之类的编造数字，**也不要**说「还在优化中」——
后者暗示这是一个未完成的功能，而实际上这是一个**已完成且有明确边界的机制**。

## 二、关于"你们宣称的东西到底在哪"

### Q4. 数字孪生在哪？我只看到 3D 模型

**一句话答**：「**可执行数字孪生**指的是 17 台设备中协议非虚拟的那部分，系统启动时
自动配对，执行后返回'虚拟预期态 ↔ 实体实测态'的比对证据。」

**展开**：这曾经**真的是坏的** —— 生产代码从未调用 `pair_twin`，`twin_pairs` 恒为空，
README 宣称的功能在运行的系统里是死的（缺陷 D11）。已修：启动时自动配对 17 台。
证据链可在 `python demo_capability_route.py` 里看到。

**现场演示**：`GET /api/capabilities` 返回 `twin_pairs` 非空；执行任一动作后
`result["twin"]["checks"]` 给出逐属性的预期/实测比对。

**不要说**：「3D 场景就是数字孪生」。那是**可视化**，不是孪生 —— 评委一听就知道
你分不清这两个概念。孪生的判别标准是**有双向的状态对照与回读校验**。

### Q5. 17 个虚拟设备算什么？

**一句话答**：「卖点不在'接了多少硬件'，而在**协议无关的能力契约**。」

**展开**：`capabilities.json` 里 `climate.set_temperature` 只声明
`device_categories: ["ac"]`，**不绑定具体设备**。未来任何空调（Matter / Home Assistant /
私有协议）只要满足这个契约，就能被同一份代码管控。这是从"设备枚举"转向"能力声明"。

**证据**：`backend/capabilities.py`、`backend/config/capabilities.json`

**不要说**：「因为没硬件所以用虚拟设备」。要说「**纯软件零硬件是刻意的验证策略** ——
它让我们能在没有采购周期的情况下把决策、护栏、融合机制全部验证完；
真实接入只需替换驱动层，能力契约不变」。

### Q6. 你们的慢环延迟到底多少？为什么超过 5 秒？

**一句话答**：「实测 **8–13 秒**，**未达标**。瓶颈是模型生成速度，不是我们的架构。」

**展开**：我们用**对照实验**定位了瓶颈（不是猜测）：

| 变动 | 结果 |
|---|---|
| prompt 51 → 1659 token（33×），输出固定 | 3551ms → 1800ms，**没有增加** |
| 输出 13 → 196 token（15×），prompt 固定 | 1277ms → **11978ms，线性增长** |

→ `耗时 ≈ 1.2s 基线 + 输出 token ÷ 15`。

**这个结论排除了三条看起来合理但实际无效的优化路线**（重构管线、压缩 prompt、批量翻译），
唯一有效的是减少输出 token 或换更快的模型。

**口径**：规则层 P50 0.11ms（确定性、无外部依赖、覆盖标准场景集 100%）；
慢环走**预算化降级，P95 有界**。

**证据**：`docs/BENCH.md` §四、`experiments/README.md` 实验五

**不要说**：「P95 < 5s」——**这是当场就能被戳穿的话**，而且戳穿成本极低
（评委让你现场跑一次即可）。

### Q7. 你们宣称决策准确率 100%，删掉 API Key 再跑一遍？

**⚠️ 这是一个设套式提问。** 正确应对是**先承认口径**：

**一句话答**：「**没有 API Key 也能跑到 100%** —— 因为那个 100% 是**规则层**的数字，
不是 LLM 的。规则层覆盖标准场景集 90/90，它本来就不调模型。」

**展开**：
- 规则层：标准场景集 S1–S11，离线 **100%（90/90）**。这是**正则与规则**的成果。
- LLM 层：单独用模糊/多步指令测（`tests_performance.py --api`），准确率随模型波动。
- **我们从不笼统宣称"LLM 决策准确率 100%"。**

**证据**：`CLAUDE.md` 第三节的"关于决策准确率"说明、`docs/BENCH.md` §一

**不要说**：「100% 是综合所有情况的」。含糊会被追问到底。

## 三、技术细节追问

### Q8. 多模态融合的三个阈值（0.5 / 0.2 / 15.0）怎么来的？

**一句话答**：「**沿用上游实现，做了行为验证，但没有做标定实验** —— 这是一个明确的
研究缺口，我们写在了可靠性报告里。」

**展开**：效果可以被单元测试验证（冲突能被检出、零信息会被拒绝），
但**它们是不是最优阈值，本项目没有做过敏感性分析**。

**证据**：`docs/感知层可靠性报告.md` §3.2

**不要说**：「经过实验确定的」。一旦评委问"什么实验"，就穿帮了。

---

### Q9. 内环告警能自动开空调，为什么情绪判断不能自动调灯？

**⚠️ 这是最容易被问倒、也最容易被认为"自相矛盾"的问题。** 必须能当场分辨：

**一句话答**：「**两者性质不同。** 内环告警是**确定性阈值判定**（读数直接比大小，
阈值写在配置里可复核），感知层是多模态**统计推断**（失效模式不透明）。」

| | 内环告警 | 感知层 |
|---|---|---|
| 输入 | 传感器读数（物理量） | 多模态统计推断 |
| 判定 | `temp_indoor > 30`，确定性 | 置信度融合 + 情境分类 |
| 阈值 | 在配置里，任何人可复核 | 权重可查，但**结论是推断** |
| 失效模式 | 传感器坏了 → 读数明显离谱 | 不透明（单模态误判、模态冲突） |
| 能否触发设备动作 | **能**（走 EventRouter，可审计） | **绝不能**（红线 1） |

**证据**：`docs/架构图.md` 图 8

**不要说**：「因为感知层还不够准」。这等于承认这是个**临时限制**；
它实际上是一条**永久的设计约束**。

### Q10. LLM 出现幻觉怎么办？

**一句话答**：「**架构兜住，不靠 prompt 祈祷。** 而且我们实测过幻觉率 —— 是 0%。」

**展开**：
1. 实测：让 Root 直接输出 `{device_id, command, params}`，**幻觉率 0%（0/25）**，
   参数越界 0，非响应对象 0/5。
2. 即使出错，`ManagerAgent._verify` 会拒绝（设备不存在 / 命令不受支持 → 丢弃并记 trace）。
3. **Root 只提议，不执行**；执行权在 Manager。
4. 四种被拒情形都有测试覆盖。

**证据**：`experiments/README.md` 实验二、`tests_agents.py`

**不要说**：「我们在 prompt 里让它不要幻觉」。这是最弱的回答 —— 说明你的防线是字符串。

### Q11. 如果现场断网 / 没有 API Key 呢？

**一句话答**：「**全链路照常演示。** 而且"降级"这件事在界面上是**可见**的。」

`LLM_OFFLINE=1` 是官方支持的演示模式。降级时前端标签从「LLM 生成」变「模板降级」，

**现场可做**：拔掉 API Key 再点一次「生成日报」，看标签变化。

**不要说**：「断网就只剩规则了，功能会少」—— 应该说
「**断网演练本身就是我们的演示脚本之一**」。

### Q12. 心镜是别人的项目，你们怎么处理许可证？

**一句话答**：「心镜是 **Apache-2.0**，我们的衍生作品权利链干净，且 `NOTICE` 里
逐项标注了每处借鉴的落点。」

**展开**：
- 本仓库选 **Apache-2.0**（而非 MIT）正是为了与心镜同许可证。
- `NOTICE` 分两类标注：「直接引用代码」与「参考设计思想后重写」。
- **实际上本项目没有复制心镜的源代码** —— 融合算法是按其机制重写（二模态→N模态），
  经验复用的是其控制流（并修掉了 `random.sample`），中间件是加锁改写。
- 明确丢弃的部分也写出来了（ORM、OrchestratorAgent、LangChain 层、心理量表）。

**⚠️ 已知待办**：`NOTICE` 中心镜部分仍写着"**待移植**"，需要更新为实际落地清单
（阶段 5 未完项）；UAgentOS 的上游仓库 URL 仍待补全。
**这两项在正式提交前必须补齐**，否则被问到会显得不严谨。

**证据**：`LICENSE`、`NOTICE`

## 四、"创新点到底是什么"（如果只允许说一条）

**一句话答**：

> 「**同一个'不信任单一信号源'的原则，贯穿感知层与执行层** ——
> 而且这两侧在代码里**共用同一个 `Gate` 抽象**，所以这不是修辞上的类比。」

**展开**：

| 层 | 单一信号源的风险 | 门控机制 |
|---|---|---|
| 感知层 | 单模态误判（光照导致面部误判等） | 多模态置信度自适应加权 + 一致性复核，冲突即丢弃 |
| 执行层 | LLM 幻觉 / 越权 / 重放 | 授权租约 + 状态版本校验 + 高危二次确认 |

两侧都是「**默认不信任、必须交叉验证、验证失败即拒绝**」，
且失败的后果都是**拒绝**而不是**执行**。

**证据**：`backend/gate.py`、`docs/架构图.md` 图 2、`tests_perception.py` 第 6 节

**为什么这条最值得说**：它是**架构层的抽象**，而不是某个功能的堆叠。
评委见过太多"我们又加了 X 功能"，少见"我们用同一个抽象统一了两个层"。

## 五、如果评委要求现场演示

**推荐顺序**（约 5 分钟，已按"先给结论再给证据"排列）：

1. **规则层亚毫秒** —— 「我回家了」，看决策链路与 3D 联动
2. **五级漏斗** —— 「窗帘开一半」证明精确规则优先于宽泛规则
3. **条件句保护** —— 「如果客厅没人就把灯关掉」→ 系统**诚实拒绝**而非误执行
   （这条最能让评委意外，因为它展示的是"不做什么"）
4. **高危二次确认** —— 「打开门锁」→ 弹窗，未确认不执行
5. **分层延迟面板** —— 打开「记忆与观测」，指出规则层与慢环**分开**显示
6. **多模态融合** —— `POST /api/perception/observe` 制造模态冲突，看门控丢弃
7. **情境看板** —— 点开任一参数看原始依据
8. **记忆召回** —— 说一句模糊指令，看决策链路里的 **RECALL** 步
9. **日报降级** —— 点「生成」，再**拔掉 API Key 点一次**，标签变化
10. **断网演练** —— `LLM_OFFLINE=1` 全流程重跑

**不要演示**：慢环实时耗时（8–13s 在答辩现场显得很卡）。若必须演示，
**先说明"这一条是慢环，实测 8–13 秒，瓶颈在模型生成速度"**，然后让它跑 ——
主动说明比等着评委计时好得多。
