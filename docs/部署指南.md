# 部署指南（本地运行 / Docker / 健康检查 / 排障）

> 目标：让"能不能落到一台盒子上"这个问题有一个可执行的答案，而不是只有演示视频。
> 本机（Windows 开发环境）未安装 Docker，**镜像构建未实测**；其余步骤均已实测通过。

## 1. 本地运行（最快）

```powershell
cd smart-home-controller
python -m pip install -r requirements.txt

# 可选：配置大模型（不配也能跑，规则层全功能）
copy .env.example .env
# 编辑 .env，填 LLM_API_KEY

python -m uvicorn backend.main:app --host 127.0.0.1 --port 8000
```

打开 <http://127.0.0.1:8000>。想给同局域网手机演示，用 `--host 0.0.0.0`
并在防火墙放行 8000（仅演示网络；**不要做公网端口转发**）。

Python 3.10+；依赖只有 6 行（fastapi / uvicorn / requests / python-dotenv /
edge-tts / apscheduler），无 opencv/faiss 这类重依赖，冷启动 <2s。

## 2. Docker（单容器）

```bash
cp .env.example .env      # 填 LLM_API_KEY
docker compose up -d --build
docker compose ps         # STATUS 应为 healthy
# 打开 http://localhost:8000
```

要点：

- 只有一个服务。灵犀的设备层是内建虚拟设备，不需要 HA/MQTT 容器；
  接真实设备时再引入适配器（见 README 后续路线）。
- 非 root 运行（uid 10001），可写目录只有 `/app/data`。
- `mem_limit: 512m`，`restart: unless-stopped`。
- `backend/config` 以只读方式挂载，改 JSON 后调 `POST /api/config/reload` 即生效。

**未实测声明**：本机没有 Docker，`Dockerfile` / `docker-compose.yml` 未经真实
`docker compose up` 验证；首次部署请预留一次排障时间（常见问题是镜像源慢、
时区数据缺失、端口占用）。

## 2.1 CSI 接入（可选，不装也能跑）

1. 节点侧：ESPectre 固件（**GPL-3.0-only，独立仓库/设备**）按官方文档配好 MQTT，
   topic 前缀为 `espectre/v1/devices/{device_id}/...`；本仓库不含其代码。
2. 后端：`pip install -r requirements-csi.txt`（只装 paho-mqtt）。
3. 配置 `backend/config/wifi_csi.json`：

```json
{"enabled": true,
 "mqtt": {"host": "127.0.0.1", "port": 1883,
          "topic_prefix": "espectre/v1/devices"},
 "nodes": [{"node_id": "node-bedroom-01", "room_id": "bedroom", "label": "卧室节点"}],
 "stale_after_seconds": 30, "sweep_seconds": 5}
```

4. 重启服务；启动日志会打印 `[CSI] MQTT 接入：已启动`。
5. 自检：

```bash
curl localhost:8000/api/csi/status
curl localhost:8000/api/rooms
```

**无硬件演示**（答辩必备）：`POST /api/csi/replay` 回放节点事件，走同一条
融合/旁证/事件链路：

```bash
curl -X POST localhost:8000/api/csi/replay -H "Content-Type: application/json" -d '{
  "records":[
    {"node_id":"node-bedroom-01","state":"motion","received_at":1760000000},
    {"node_id":"node-bedroom-01","state":"idle","received_at":1760000001},
    {"node_id":"node-bedroom-01","state":"idle","received_at":1760000302}
  ]}'
```

> `idle` 302s 且旁证一致才会出 `empty_confident`；299s 仍 `uncertain`。
> 旁证（PIR/插座/门磁/作息）当前为仿真量，证据里标 `source_kind="simulated"`。

## 3. 健康检查

| 端点 | 认证 | 用途 |
|---|---|---|
| `GET /healthz` | 无 | 容器 healthcheck；只返回 ok / version / uptime / 三项检查 |
| `GET /api/health` | 无 | 诊断：版本、状态版本号、设备数、工具数、草稿箱、LLM 状态 |
| `GET /api/metrics/llm` | 无 | 分层延迟（规则层 vs 慢环）、降级率、最近调用 |
| `GET /api/metrics/api` | 无 | 接口统计、限流、感知/告警状态 |

`/healthz` 设计成无认证，是因为 Docker healthcheck 在容器内跑、没有登录态。
它**不返回设备名/房间/家庭信息**（`tests_agents.py` 有断言守门）。

为什么需要它：`restart: unless-stopped` 只能救"进程退出"，救不了"进程活着但事件
循环冻结"——灵犀把所有后台循环（传感器/告警/感知）挂在同一个 loop 上，这正是
7×24 部署里最隐蔽的失效模式。

## 4. 环境变量

| 变量 | 必填 | 说明 |
|---|---|---|
| `LLM_BASE_URL` / `LLM_API_KEY` / `LLM_MODEL` | 否 | OpenAI 兼容端点；不配则只用规则层 |
| `LLM_TIMEOUT` | 否 | 单次调用超时（秒），默认 30；慢环另有 `llm_budget` 兜底 |
| `LLM_OFFLINE` | 否 | `1` = 强制不出网（断网演练/回归测试） |
| `XIJIAN_DATA_DIR` | 否 | 运行时状态目录（优先）；`LINGXI_DATA_DIR` 作为旧名回退；默认 `<repo>/data` |
| `TZ` | 否 | 时区，日报/定时任务按它算；容器内已设 `Asia/Shanghai` |

## 5. 配置热重载

设备、场景、告警阈值、事件路由、信任层、工具裁剪、草稿规则、房间融合、
六路旁证、L5 自治都在 `backend/config/*.json`，改完调：

```bash
curl -X POST http://localhost:8000/api/config/reload
```

会一并失效回读参数、裁剪缓存、声明校验缓存，重载自定义事件路由
（`data/event_routes_custom.json`）、房间配置与自治配置。无信号裁剪、无重启。

**L5 默认关闭**：`adaptation.json → enabled=false`。要用时改 `true`，
先跑 `GET /api/adaptation` 看偏好带（样本 <12 只给区间），
再 `POST /api/adaptation/tick` 看提议与四道闸；`auto` 需同时满足等级与模式。

## 6. 断网演练

```powershell
$env:LLM_OFFLINE="1"
python -m uvicorn backend.main:app --port 8000
```

规则层、感知层、告警、日报模板降级、条件句草稿全部可用；慢环降级会写进
`decision_trace` 与 `/api/metrics/llm`（降级必须可见）。

## 7. 回归门禁

```powershell
python run_tests.py            # 15 个脚本，自动 LLM_OFFLINE=1 + 临时数据目录 + UTF-8
python run_tests.py --verbose  # 看完整输出
python run_tests.py --only tests_agents.py tests_loops.py
```

不要手敲 `python tests_xxx.py` 做门禁：不设 `LINGXI_DATA_DIR` 会污染真实数据，
不设 `PYTHONIOENCODING=utf-8` 会在 GBK 控制台把"全过"显示成"全红"。

## 8. 常见故障

| 现象 | 原因 | 处理 |
|---|---|---|
| 测试打印 `UnicodeEncodeError: 'gbk'` | 控制台编码 | 用 `run_tests.py`，或 `$env:PYTHONIOENCODING="utf-8"` |
| 启动报 `ModuleNotFoundError: apscheduler` | 依赖没装全 | `pip install -r requirements.txt`（缺失时服务会降级，不崩） |
| 慢环很慢（8–13s） | 模型生成速度是硬约束，不是网络/prompt | 换更快模型或本地推理；不要重构管线（实验已证伪） |
| `/healthz` 打不通但进程在 | 事件循环被同步调用卡住 | 查是否有阻塞调用没走 `asyncio.to_thread`；容器会因 healthcheck 失败自动重启 |
| `data/` 写不进去 | 容器挂载属主不对 | 宿主机 `./data` 权限给 uid 10001，或删掉重建 |
| 改 JSON 不生效 | 缓存 10s / 未 reload | `POST /api/config/reload` |
| 条件句只回"不会立刻执行" | 条件词未命中 `draft_rules.json` | 在配置里补关键词，或在界面手工建规则 |

## 9. 升级与回滚（简版）

1. 备份：整个 `data/` 目录 + `.env`。
2. 拉新代码 → `docker compose up -d --build`（或本地重启 uvicorn）。
3. 回滚：切回上一份代码/镜像，恢复 `data/`。
4. 版本号看 `/healthz` 的 `version` 或 `backend/version.py`（单一出处）。

数据格式变更（目前没有数据库）只涉及 `data/*.json|jsonl`；升级前备份即可回滚。
