# 犀鉴 · 五层架构与创新点

> 对外口径：**更安全、更智能的智能家居系统**。
> 安全 = 隐私（不采图像/声音）+ 行为安全（可审计、可撤销、高危拒绝）；
> 智能 = 全屋统一接管 + L5 目标级自主。
> 本文只写**能在代码里指到**的东西；未实测的数字一律留空。

## 一、要解决的问题

家庭智能化的瓶颈已经从"设备能不能接入"变成"系统该不该动作"：

- 这一间房此刻有没有人？
- 判不准时，系统是猜，还是如实说"不确定"？
- 动作出错后，能不能收回？
- 节点掉线时，房间状态怎么变？

现有手段各有边界：PIR 对静坐失效；毫米波需专用硬件、固定角度、单房间；
摄像头进不了卧室/卫浴且隐私事件频发；可穿戴需要配合佩戴。
Wi-Fi CSI 不采图像与声音、复用已有 2.4GHz 网络、被感知者无需配合——但它有一个
被普遍忽略的语义缺口：**`idle` 只表示"没有运动"，不等于"房间无人"**。

犀鉴的增量就在这个缺口上：不做射频前端，做**全屋房间级三态判定 + 降级语义 + 可信执行**。

## 二、五层架构（与代码落点）

| 层 | 职责 | 代码 |
|---|---|---|
| ① 射频基线 | CSI 采集 + 单点运动检测，独立仓库/设备运行 | 外部 ESPectre（GPL-3.0），本仓库只消费 MQTT/HTTP 事件 |
| ② 房间融合 | 多节点状态机 → 房间四态；节点冲突与掉线降级 | `backend/perception/rooms.py`、`ingest/node_registry.py` |
| ③ 多源校验 | 六路旁证交叉验证；冲突归因；只有一致才提升 empty | `backend/perception/corroboration.py`、`room_service.py` |
| ④ 信任层 | 六段因果链、10 分钟撤销、高危拒绝、失败归因 | `backend/execution.py`、`trust/explain.py`、`trust/undo.py` |
| ⑤ L5 自治 | 偏好带、目标仲裁、四道闸、冷启动、漂移降级 | `backend/adaptation/` |

四个后台环：传感器 2s / 告警 5s / 房间 5s / 感知 15s / 自治 60s（`config/loops.json`）。

## 三、四个可辩护的创新点

### 1. 三态判定，四值实现（不是"有人/无人"两态）

`present_confident / empty_confident / uncertain / degraded`。
`uncertain` 是**刻意的输出**，不是失败：人静坐、多人、宠物、节点冲突都归到这里，
不硬判无人。`degraded` 只下调置信度并告警，**永不推断无人**。

代码：`rooms.py::fuse_rooms()` 全部节点 idle 只置 `empty_candidate=True`；
`corroboration.py::corroborate()` 才可能提升为 `empty_confident`。

### 2. 六路旁证 + 冲突归因（不是调阈值）

CSI / PIR / 插座功率 / 设备操作 / 作息基线 / 门磁。仅当 CSI 无运动、
**≥2 路旁证一致**、且持续超过阈值，才判无人；任一源冲突 → `uncertain`，
并分类为 `human / pet / environment / fault / unknown`。

代码：`corroboration.py`；配置：`config/room_fusion.json → corroboration`。
当前除 CSI 外为仿真量，证据标 `source_kind="simulated"`。

### 3. 六段因果链 + 可撤销执行

`signal → inference → gate → lease → action → readback`，统一 `decision_id`。
失败归因到 `sensor / inference / gate / lease / device / readback`。
可逆动作保留前态，10 分钟内可撤销；撤销前做**漂移校验**（当前值必须仍等于 after，
否则拒绝覆盖他人操作）。高危动作永不自动执行。

代码：`execution.py`（唯一写入口）、`trust/explain.py`、`trust/undo.py`。

### 4. L5 目标级自主（不是"多几条自动化"）

按能力属性（温度/湿度/风速/开合度/时间表）学偏好带，而不是按设备型号写规则；
多设备围绕同一目标确定性协商（空调 vs 除湿机、热水器峰谷），
四道闸（包络/步长/间隔/预算）约束，冷启动影子→探测→自动，
指标越限按 `auto → confirm → suggest_only → off` 退让。

代码：`adaptation/preference.py`、`objectives.py`、`policy.py`。

## 四、与同类方案的差异

| 方案 | 能覆盖全屋 | 隐私 | 判不准时 | 出错可撤 | 成本/房间 |
|---|---|---|---|---|---|
| PIR | 可多房间 | 好 | 静坐失效（误判无人） | 无 | <30 元 |
| 60GHz 毫米波 | 单房间 | 较好 | 幽灵存在、需重标定 | 无 | 数百元 |
| 摄像头 | 可多房间 | 私密区不可用 | 置信度不透明 | 无 | 百元级 |
| 可穿戴 | 需佩戴 | 好 | 摘除即失效 | 无 | 百元级 |
| 商用中枢 | 编排层 | 取决设备 | 只记日志 | 无动作级撤销 | — |
| **犀鉴** | **多节点→房间→全屋** | **不采图像/声音** | **显式 uncertain + 归因** | **10 分钟撤销** | **≤100 元** |

## 五、自研边界与许可证

- 射频基线：ESPectre v3.1.0（GPL-3.0-only），独立运行；本仓库只消费其 MQTT/HTTP 事件契约，
  **不复制代码、不分发固件/数据集**（见 `NOTICE` 第 3 条）。
- 自研四层：房间融合、三态判定、信任层、L5 自治。
- 判据可经第三方核查：在仓库里搜 `fuse_rooms` / `corroborate` / `execute_action` /
  `learn_bands`，均能指到实现与测试。

## 六、当前能证明什么、不能证明什么

**能证明（本地可复现）**

- 三态与降级语义：`tests_csi.py` 103 项（299s vs 302s 边界、掉线→degraded、单源不得判无人）；
- 六段链与撤销：`tests_trust.py` 48 项（五层归因、四道闸、5 类撤销、窗口、漂移、高危无记录）；
- L5 规则：`tests_adaptation.py` 28 项（偏好带、仲裁确定性、冷启动、降级、安全排除）；
- 一条命令门禁：`python run_tests.py` 15/15。

**不能证明（必须等实测）**

- 真实 ESP32 节点在未标定家庭中的三态稳定性；
- 空房间每小时误报 ≤2 次、静坐漏报 ≤20%；
- 3–5 户家庭 2–4 周部署的自动执行占比、撤销率、复发率、能耗变化；
- L5 三项判据（≥90% / 3 天 / 7 天）。

这些是申报书阶段一/三的交付项，**当前一个数字都不填**。
