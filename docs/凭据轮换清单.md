# 🔐 凭据轮换清单

> 背景：本项目（灵犀）的 `.env` 里曾长期放着一枚**真实的智谱 API Key**（CLAUDE.md D9）。
> 2026-11-24 已核实：`git log --all -- .env` 无任何提交，**密钥没有进过 git 历史**。
> 但"没进 git"不等于"没泄露"——桌面压缩包、同步盘、截图、远程协助都可能带走它。
> 轮换是唯一根治，历史清理不是。

## 0. 先自查（2 分钟）

```powershell
cd smart-home-controller

# 1) .env 是否被 git 跟踪（应输出空）
git ls-files .env

# 2) 历史上是否有过 .env（应输出空）
git log --all --oneline -- .env

# 3) 当前工作区里有没有密钥被其它文件带出来
git grep -nE "sk-[A-Za-z0-9]{16,}|LLM_API_KEY=.+[A-Za-z0-9]" -- . ":(exclude).env"

# 4) 确认 .env 在忽略列表里
git check-ignore -v .env
```

## 1. 轮换大模型 API Key（最高优先级）

- [ ] 打开对应控制台（智谱 / DeepSeek / 通义 / Moonshot）→ API Key 管理
- [ ] **删除**旧 Key（不是禁用）
- [ ] 新建 Key，复制新值
- [ ] 更新 `.env`：`LLM_API_KEY=<新值>`
- [ ] 重启服务（或调用 `POST /api/config/reload` 后重启更稳妥，Key 走进程环境变量）
- [ ] 验证：`/healthz` 的 `llm_configured=true`；`/api/chat` 发一句模糊指令（走慢环）能回

> 换 Key 后建议跑一次 `python run_tests.py`（`LLM_OFFLINE=1` 强制离线，不会消耗额度）。

## 2. 若将来接入真实设备

- [ ] Home Assistant 长期访问令牌 / Matter 配网码：只写 `.env`，不进 `config/*.json`
- [ ] MQTT 用户名密码：同上；broker 端口只绑回环，不要 `0.0.0.0`
- [ ] 摄像头 RTSP 账号密码：用 `RTSP_PASSWORD` 这类环境变量引用，配置文件里只留变量名
- [ ] 门锁/燃气灶的厂商云账号：能本地就本地，不要为便利开公网回调

## 3. 若将来引入登录/多用户

- [ ] `JWT_SECRET` 用随机 32 字节以上，只放 `.env`，不写默认值
- [ ] 首次部署的注册码/邀请码：一次性、24h 过期、可吊销
- [ ] 泄露处置顺序永远是：**先轮换 → 再改代码 → 最后才谈历史清理**

## 4. 长期卫生（写进习惯）

1. `.env` 永远不提交；提交前 `git status` 看一眼。
2. 日志不打印密钥：`llm_client.get_status()` 只返回 `available/base_url/model`，不返回 key。
3. 诊断包/截图/演示视频发布前，检查右下角是否带出了 Key 或家庭地址。
4. 每换一台机器/每半年，按本清单过一遍。
5. 如果确实误提交了：`git filter-repo` 清理历史 **+ 立刻轮换**，两件事都要做。
