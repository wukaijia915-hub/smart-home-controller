# 感知层可靠性报告

> **本报告的目标不是证明感知层准确，而是说清它在什么条件下可信、在什么条件下不可信。**
>
> 这个定位来自一个明确的判断：**非接触式家庭感知领域，"声称高准确率"远比
> "如实报告边界"更可疑。** 心镜自测的负面数据（见 §四）就是最好的例子 ——
> 它最亮眼的模块恰恰是它自己证伪的。
>
> 配套文档：融合算法见 `docs/架构图.md` 图 6 与 `docs/融合技术白皮书.md` §4.1；
> 硬边界见 `CLAUDE.md` 红线 1。

---

## 一、报告方法论

本报告对每一路模态回答四个问题：

| 问题 | 为什么问 |
|---|---|
| **数据从哪来？** | 软件阶段有仿真成分，必须说清楚哪部分是真实的 |
| **可用性如何判定？** | "不可用"与"判定为中性"必须能被区分（否则失败被伪装成正常） |
| **验证到什么程度？** | 有没有真值？能不能算混淆矩阵？还是只是工程映射？ |
| **失效时怎么办？** | 是丢弃、降权，还是照常参与？ |

**总原则**：宁可**明确不可用**，也不输出一个看起来合理但没有依据的中间值。
这条原则在融合层的落点是：零信息 → 零置信度 → 拒绝，而**不是**回退到 0.5。

## 二、四路模态逐项评估

### 2.1 视觉行为模态 —— 最可靠的一路，但请注意它是模拟的

| 项 | 说明 |
|---|---|
| 实现 | `perception/modalities/vision_behavior.py`，复用 `multimodal.py::VisionEventDetector` |
| 数据来源 | ⚠️ **软件阶段由关键词模拟端侧视觉小模型的输出**（`scene_hint` 传入"跌倒"/"有人"/"无人"/"隐患"） |
| 行为契约 | 与真实端侧推理一致：**画面本地处理，只输出结构化事件结论** |
| 输出 | 离散事件（`fall_detected` / `safety_hazard` / `person_present` / `no_person`） |
| 验证程度 | 可算混淆矩阵（离散事件有明确真值），**但当前没有真实画面数据集，因此没有实测混淆矩阵** |
| 失效时 | 无事件 → 该模态不产生读数，**不填中性值** |

**为什么说它"最可靠"**：视觉事件是**离散的、有明确真值的**检测结果（有人在/没人/摔倒了），
不像情绪测量那样需要心理测量学验证。

**为什么必须标注"模拟"**：这一路当前的价值在于**验证融合与门控机制**，
不在于证明视觉算法本身。接入真实模型（YOLO / 姿态估计）后，本节的"验证程度"
一栏才能填上真实数据。**在那之前不要在任何材料里写"视觉识别准确率 X%"。**

### 2.2 环境行为模态 —— 唯一完全真实的一路

| 项 | 说明 |
|---|---|
| 实现 | `perception/modalities/environment_behavior.py` |
| 数据来源 | **真实传感器读数**（温湿度/光照/空气质量/人体红外）+ **真实操作日志**（`StateStore.audit_log`） |
| 输出 | 活动强度、舒适度偏差等连续量 |
| 验证程度 | 由 5 个白盒情境参数逐项给出真值来源与原始依据，可展开复核（前端「家庭情境看板」） |
| 失效时 | 读数缺失或非数值 → **不参与**（`tests_loops.py` 断言：缺测不被当成越界） |

**这是感知层里唯一没有任何仿真成分的一路**，也是答辩时最经得起追问的一路。
它对应 `docs/架构图.md` 图 8 中「内环告警」那一侧的数据源。

**注意它与内环告警的区别**：同一个传感器读数，走内环告警是**确定性阈值判定**
（允许触发设备动作），走感知层是**统计推断的一部分**（绝不允许）。二者性质不同，
见 `docs/架构图.md` 图 8。

### 2.3 面部表情模态 —— 演示级，四条边界写死在代码里

| 项 | 说明 |
|---|---|
| 实现 | `perception/modalities/facial_expression.py`，DeepFace 7 类 FER |
| 数据来源 | 摄像头帧（**可选依赖**，见 `requirements-vision.txt`） |
| 验证程度 | **无**。公开 FER 基准约 65–70%，本项目不做任何准确率承诺 |
| 失效时 | 依赖未安装 → `available()=False`，该模态静默缺席（不算失败，`tests_perception.py` 断言优雅降级） |

**四条边界（代码注释里逐条写明，此处复述）**：

1. **演示级，非医学级。** 用现成的 7 类表情分类器，**不做准确率承诺**，
   不当作心理测量工具。
2. **不产生任何设备动作。** 由感知层的硬边界保证（静态扫描 + `PERCEPTION_CANNOT_ACTUATE`）。
3. **画面本地处理，仅概率分布参与融合。** 原始帧不出本机。
4. **光照等条件会显著影响判定** —— 这正是多模态一致性复核存在的理由（见 §三）。

### 2.4 前庭振动模态 —— 接入它，是为了用交叉验证管住它

| 项 | 说明 |
|---|---|
| 实现 | `perception/modalities/vestibular.py` —— **适配器**，不含引擎本体 |
| 数据来源 | 由外部引擎算好后传入（`PerceptionContext.vestibular`） |
| 验证程度 | **心镜自己的评测报告已证伪**，见 §四 |
| 失效时 | 无数据 → 该模态缺席 |

**本项目不移植 VibraImage 引擎本体**（约 3000 行）。理由不是"代码不好"，
而是**它的验证数据不支持把它当作测量工具**。这里保留的只是一个**接入位**，
让"用多模态一致性检验管住一个弱信号"这件事可以被演示和讨论。

## 三、融合机制本身的可靠性

### 3.1 单模态误判 + 融合纠正（结构照搬心镜 3.2.1 的实验设计）

心镜技术报告记录过一次真实视频消融：一段 happy 视频因**光照导致面部侧误判为焦虑**
（`mouth_curve = -0.93`），而前庭侧输出正效价 0.668，**融合后正确判为开心**。

本项目用同样结构做了单元级验证：`tests_perception.py` 的模态冲突场景 ——
`scene_hint="无人"`（视觉：低唤醒）配 8 条近期操作（环境行为：高唤醒），
两者欧氏距离 **0.95 > 0.5 阈值** → 门控 `passed=false`，整组结果丢弃。

> **注意这个实验测的是"冲突能不能被检出"，不是"融合能不能还原真相"。**
> 后者需要带真值标注的数据集，本项目没有。**这是本报告最重要的边界声明。**

### 3.2 三个阈值是怎么来的

| 常量 | 值 | 来源与说明 |
|---|---|---|
| `MAX_STD_FOR_CONFIDENCE` | 15.0 | 移植自心镜。含义：一次读数序列的标准差达到 15 时置信度归零 |
| `MODAL_DISTANCE_THRESHOLD` | 0.5 | 移植自心镜。含义：模态间最大两两欧氏距离超过 0.5 判为冲突 |
| `MIN_FUSED_CONFIDENCE` | 0.2 | 融合置信度低于此值不给建议 |

**这三个值是移植来的，不是在本项目上标定的。** 它们的效果可以被单元测试验证
（冲突能被检出、零信息会被拒绝），但**它们是不是"最优"阈值，本项目没有做过
敏感性分析或标定实验**。

> **这是一个明确的研究缺口，写在这里而不是藏起来。** 一个诚实的说法是：
> "阈值沿用上游实现并做了行为验证，尚未做标定"。不诚实的说法是
> "经过实验确定的阈值"。

### 3.3 融合的一致性与确定性

| 性质 | 保证 | 验证 |
|---|---|---|
| 确定性 | 同样输入必得同样输出（无随机数、无时间依赖之外的隐式状态） | `tests_perception.py` 多次断言 |
| 时间可注入 | `PerceptionContext.now` 可显式指定判定时刻 | `tests_perception.py` 有一对断言（同样输入换到下午就不再判为深夜异常） |
| 不出网 | 四路模态全部端侧处理 | `tests_perception.py` 第 5 节断言 `local_only` |
| 不执行 | 感知层无设备执行能力 | `tests_perception.py` 第 7 节**静态扫描** |

> **时间可注入这条不是学术洁癖**：`late_night_activity` 规则在 23:00–05:00 生效，
> 而测试原本用 `datetime.now()` —— 同一份代码 22:00 跑是绿的、23:01 跑就红
> （实测复现：三条断言全红而代码一行没改）。凡是"结果取决于跑测试的钟点"的断言
> 都是定时炸弹：深夜演示或凌晨 CI 会莫名其妙地红，且没人会想到是时间导致的。

## 四、心镜 VibraImage 的负面数据（原文摘要）

心镜最亮眼的卖点之一是 VibraImage 前庭振动引擎（约 3000 行、专著公式、10266 人常模）。
**但它自己的评测报告与论文实验给出了如下数据**：

| 证据 | 数据 |
|---|---|
| 参数显著性 | 14 个参数修复后仅 **2/14** ANOVA 显著 |
| 重测信度（ICC） | **多为负值**（aggression −0.47、charm −0.39） |
| 微运动特征对效价的预测力 | **r = 0.021**（≈ 无信号） |
| 内容基线的预测力（对照） | r = 0.692 |

**ICC 为负值意味着什么**：重测信度的合理范围是 0–1，负值表示
**测量结果比随机猜测还差** —— 同一受试者两次测量之间没有一致性。

**本项目的处理**：

1. 作为**第四感知模态**接入，而非情绪判定器
2. 用**多模态一致性检验**管住它 —— 冲突即丢弃
3. 绝不进入控制回路
4. 文档里如实写出上述数据（本节）

> **一个值得指出的细节**：多模态一致性检验这个机制，**心镜自己的融合模块里已经有了，
> 但它没有用它来管住 VibraImage**。本项目把这两块接起来。
>
> 换句话说：**我们不引入一个新的测量方法，我们引入的是一个已被证伪的信号，
> 并用上游自己发明但未使用的机制给它套上笼子。** 这个"引入信号 → 管住它 → 如实报告
> 边界"的完整链条，比声称高准确率更经得起追问。

## 五、已知失效模式清单

| # | 失效模式 | 后果 | 当前处理 | 是否已测 |
|---|---|---|---|---|
| 1 | 视觉输入无事件 | 该模态缺席 | 不填中性值 | ✅ |
| 2 | 传感器读数缺失/非数值 | 该模态缺席 | 不参与判定，**不误报越界** | ✅ |
| 3 | 面部依赖未安装 | 该模态缺席 | 静默降级，系统照常运行 | ✅ |
| 4 | 模态间数据矛盾 | 融合结果不可信 | 一致性复核 → 整组丢弃 | ✅ |
| 5 | 全部模态无依据 | 无结论 | 零置信度 + 拒绝（**不制造 0.5**） | ✅ |
| 6 | 光照导致面部误判 | 单模态错误 | 由 4 兜住（前提是其他模态提供了有效信号） | ⚠️ 结构上支持，**无实测数据** |
| 7 | 传感器漂移（缓慢偏移） | 舒适度判定偏移 | **无处理** | ❌ |
| 8 | 多人同时在家 | 活动强度被平均 | **无处理** | ❌ |
| 9 | 阈值非最优 | 可能误判/漏判 | 已关注但未标定（§3.2） | ❌ |
| 10 | 感知结果被误用于控制 | 违反红线 | **静态扫描强制**（架构不变量） | ✅ |

**第 7–9 项是本报告的明确缺口**，它们不影响演示，但会影响"长期真实部署"这个主张。
在材料里**不要**把感知层描述成"已在真实家庭长期运行验证"。

## 六、我们不做的事

| 不做 | 原因 |
|---|---|
| 情绪测量 | 见 §四：非接触式情绪识别在公开验证中 ICC 多为负值 |
| 任何准确率承诺 | 没有带真值标注的数据集 |
| 声称"已在真实家庭验证" | 软件阶段，无长期部署 |
| 把感知结果用于自动控制 | 红线 1，静态扫描强制 |
| 把国产算力写成成果 | 感知层当前**无计算密集负载**（一次评估 0.088ms），没有可加速的对象 |
| 声称阈值经过标定 | 阈值沿用上游实现，见 §3.2 |

## 七、答辩必答

> **"你们的感知层准确率是多少？"**
>
> 「**这个问题我们不给数字，因为给不出有依据的数字。**
>
> 感知层的四路模态里，只有环境行为这一路是完全真实的（真实传感器读数 +
> 真实操作日志）；视觉行为当前是**关键词模拟**，它的价值在于验证融合与门控机制，
> 不在于证明视觉算法；面部表情是**演示级**，公开 FER 基准约 65–70%，我们不做承诺；
> 前庭振动这一路，**上游项目的自测数据显示 14 个参数只有 2 个 ANOVA 显著、
> 重测信度 ICC 多为负值**。
>
> 所以我们报告的是一条**可靠性链**，而不是一个准确率：每一路模态的数据来源与
> 失效模式都写在 `docs/感知层可靠性报告.md` 里，融合层的三个阈值是沿用上游实现
> 而非本项目标定 —— 这一点我们也写清楚了。
>
> 我们能保证的是：**单模态误判不会穿透到下游**。模态间矛盾时整组结果被丢弃，
> 零信息时不给建议而不是给一个 0.5，而且感知层在架构上**没有执行设备的能力**，
> 这条由静态扫描的测试强制。」

## 八、若要继续推进，优先级如下

| 优先级 | 事项 | 收益 |
|---|---|---|
| 高 | 接入真实视觉模型（YOLO/姿态估计），补混淆矩阵 | 让"最可靠的一路"从模拟变成实测 |
| 高 | 做阈值敏感性分析（`MODAL_DISTANCE_THRESHOLD` 0.5 是否合适） | 把移植来的常量变成标定过的常量 |
| 中 | 采集带真值标注的家庭场景数据（哪怕是自录小样本） | 让"融合能还原真相"这个主张可验证 |
| 中 | 传感器漂移检测、多人场景处理 | 补上 §五 的 7、8 项 |
| 低 | 接入 MUSA/CUDA 加速链 | **仅在接入真实视觉负载之后**才有意义 |
