# 安全与稳定性排查报告（v1.1，2026-11-24）

> 定位前提：单用户、家庭内网、可断网运行的技术原型；**不是**公网多租户服务。
> 本报告只记录**经源码复核与回归测试验证**的问题与修复。每条都能指到文件与守门测试。
> 未做的事写在最后，不拿"计划中"冒充"已完成"。

## 一、本轮（v1.1）新发现并修复

> 背景：本轮把对照项目 Aether 的工程实践落进灵犀。改造过程中**顺手发现了 5 个
> 既有洞/缺口**——它们不是"为了新功能而改"，是原先就存在的执行链旁路与验证盲区。

### N1【高】执行链存在 5 条旁路，只有对话和工具走了护栏

| | 内容 |
|---|---|
| 问题 | `/api/control`、WS `control`、`/api/scene`、WS `scene`、`/api/skills/{id}/execute` 都直接调 `registry.control()`，绕过租约、版本校验、高危二次确认、审计 |
| 根因 | D22 只在工具层修过同一个洞（`toolkit/guard.py`），其余入口没有统一；"Manager 是唯一执行入口"只是文档承诺 |
| 修法 | 新增全局 `manager_guard`；5 个入口全部改走 `ManagerGuard.actuate`（技能层经可选 `actuate` 参数注入，保留"高危不得批量执行"的拒绝） |
| 守门 | `tests_agents.test_single_chokepoint`（审计+版本递增）、`test_no_direct_control_in_routes`（AST 扫描 `main.py`，禁止 `registry.control(` 调用） |

### N2【高】对话路径没有参数包络

| | 内容 |
|---|---|
| 问题 | 工具路径有 schema 校验（min/max/enum），但 LLM/规则提议的动作直接进执行体。`{"brightness": 500}` 依赖虚拟设备 clamp；真实适配器可能原样下发 |
| 根因 | 包络只写在工具层，而对话路径不经工具注册表 |
| 修法 | `ManagerAgent._verify_params()`：按 `toolkit.schema_gen.PARAM_SOURCE` + 设备属性元数据校验数值范围/枚举/布尔；高危确认后再执行时**再校验一次**（挂起期间配置可能变） |
| 守门 | `tests_agents.test_param_envelope`（99℃ / 500% 被拒、26℃ 通过） |

### N3【中】"回读没核实"与"回读不符"混为一谈

| | 内容 |
|---|---|
| 问题 | `status=delivered` 只表示"未 confirmed"，但没记录**为什么**：是没有回读契约、回读值是 `unknown`、还是值与预期不符 |
| 根因 | 证据形状只有 `{attribute, expected, actual, confirmed}` |
| 修法 | 增加 `trusted` / `reason` / `checked_at`；`unknown/unavailable/空值` 判为"不可信"而不是"符合预期"；回读参数（传播等待、数值容差、不可信名单）外置到 `trust.json → readback`，带 10s TTL 缓存 + reload 失效 |
| 守门 | `tests_agents.test_readback_evidence`、`test_untrusted_readback_not_confirmed` |

### N4【中】回复侧无人管：模型可以"嘴上说做完了"

| | 内容 |
|---|---|
| 问题 | Manager 保证"执行真实发生"，但回复文本没有任何核对。模型只调了灯，却可以说"已把空调调到 26 度"；一个动作都没提议，也可以说"已为您打开客厅灯" |
| 根因 | 验证只覆盖"提议→执行"，没覆盖"执行→表述" |
| 修法 | 新增只读层 `backend/verification/claim_checker.py`：三时态正则 → 设备指称匹配（名称优先、类别+房间收敛、动过的设备收敛）→ 对照本轮结果判定 `untouched_device / failed_but_claimed / command_mismatch / unverified / creation_without_evidence` → 追加如实注记 + trace 留痕。可回退：`trust.json → claim_check.enabled/rewrite_reply` |
| 守门 | `tests_agents.test_claim_check`（四类都能识别）、`test_claim_check_wired`（接入 decide 后追加上下文）、`test_verification_layer_is_readonly`（AST：不得 import 设备层/租约层） |

### N5【中】条件句只能"诚实拒绝"，能力缺口被当成设计

| | 内容 |
|---|---|
| 问题 | 「如果客厅没人就把灯关掉」旧行为是拒绝并指路（D18）。诚实，但产品上等于"做不到" |
| 修法 | 草稿→确认两段式：`drafts.py`（内存、10 分钟 TTL、容量上限、线程安全）+ `draft_rules.json`（条件→事件声明式映射）+ 动作解析复用漏斗④⑤ + 确认后写入 `data/event_routes_custom.json`。**解析不出来仍回到拒绝**，不猜 |
| 边界 | 草稿不是动作（无租约、不执行）；高危动作在**确认时**还要显式 `allow_high_risk`，否则整条拒绝 |
| 守门 | `tests_loops` 第 6 节 13 项：不执行 / 草稿形状 / 确认落库 / 事件真触发 / 回读证据 / 无法解析仍拒绝 / 高危未允许被拒 / 显式允许后执行 / TTL 清理 |

### N6【中】64 个工具、17 台设备一次全暴露

| | 内容 |
|---|---|
| 问题 | MCP `tools/list` 与慢环 prompt 都是全量。工具越多选择精度越低（Aether 把 22 砍到 17 的实证） |
| 修法 | `toolkit/scoping.py`：按房间/类别/设备名裁剪，**无信号不裁剪**（模糊指令保留全量），高危命令默认不可见（仅显式提到才放出）；接入慢环 prompt、`/api/tools?intent=`、`/api/tools/scope`、MCP `tools/list params.intent` |
| 守门 | `tests_funnel` 第 8 节 10 项（17→3、64→12、无信号不裁、高危隐藏/显式放出、prompt 行数） |

### N7【低但真】能力别名把"解锁"解析成"上锁"

| | 内容 |
|---|---|
| 问题 | 「解锁门锁」同时包含「解锁」(pos 0) 与「锁门」(pos 1)。旧 `resolve` 只按长度稳定排序，命中「锁门」→ 方向完全相反 |
| 修法 | 排序键改为 `(len(keyword), -pos)`：更长优先，等长取**出现更早**的关键词 |
| 守门 | `tests_loops` 高危草稿断言（草稿里必须是 `unlock` 而不是 `lock`）+ `tests_capabilities` 30 项回归 |

### N8【中】没有存活探针，也没有容器化

| | 内容 |
|---|---|
| 问题 | `restart: unless-stopped` 救不了"进程活着但事件循环冻结"；交付问题没有答案 |
| 修法 | 无认证 `GET /healthz`（不泄露设备信息）+ `GET /api/health` + `Dockerfile`（非 root/HEALTHCHECK）+ 单服务 `docker-compose.yml`（mem_limit/restart/只读配置挂载） |
| 守门 | `tests_agents.test_healthz_and_scope_endpoints`（契约 + 不泄露） |
| 遗留 | **镜像未实测构建**（本机无 Docker） |

### N9【中】回归门禁本身不可复现

| | 内容 |
|---|---|
| 问题 | 13 个脚本靠手敲：漏 `LLM_OFFLINE=1` 会打真实模型（结果 flaky）、漏 `LINGXI_DATA_DIR` 会写真实数据、GBK 控制台把 ✓ 打成异常导致"假红" |
| 修法 | `run_tests.py`（自动离线 + 临时数据目录 + UTF-8 + 超时 + 汇总）+ CI（push/PR 跑同一条命令） |
| 验证 | 13/13 通过，总耗时约 9s |

## 五、不能声称什么（诚实边界）

- 不能说"已支持真实智能家居"——设备是虚拟的（19 台），协议适配是占位。
- 不能说"感知层已用真实视觉模型"——模态是模拟数据，混淆矩阵未做。
- 不能说"多用户/公网安全"——没有登录体系，CORS 全开，仅限内网。
- 不能说"慢环 P95 <5s"——实测 8–13s，靠预算化降级兜住，不是靠优化。
- 不能说"Docker 已交付验证"——未构建过镜像。
- 不能说"自进化/自学习"——经验复用是 prompt 级案例注入，没有梯度更新。
- 不能说"Wi-Fi CSI 已实测"——**没有 ESP32 节点、没有自采数据**；
  房间三态、误报/漏报、L5 三项判据全部待阶段一/三实测。
- 不能说"六路旁证都是实测"——除 CSI（契约）与设备操作（审计）外，
  PIR/插座/门磁/作息为仿真量，证据标 `source_kind="simulated"`。
- 不能说"已实现 L5 自主"——只能说是"L5 的决策框架与可测口径已落地，
  `enabled=false`，真机验证在阶段三"。
- 不能说"跌倒检测/人数统计/身份识别"——申报书明确不做，代码里也没有。
