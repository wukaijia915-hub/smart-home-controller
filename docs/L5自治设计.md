# L5 自治设计（有界目标级自主）

> 一句话：**L5 不是"多几条自动化"，而是"按能力属性学偏好带 + 多设备围绕同一目标协商 +
> 在四道闸内免确认执行 + 出错能收回"**。
> 与 L4 的分界是**人工介入程度**，不是识别准确率。

## 一、L0–L5 分级（本项目自划，逐级给判据）

| 级别 | 名称 | 判据 |
|---|---|---|
| L0 | 手动 | 无自动化 |
| L1 | 定时/场景 | 固定时刻或一键场景 |
| L2 | 条件触发 | 传感器 → 规则 → 动作 |
| L3 | 单设备学习 | 只学一台设备，执行前需确认 |
| L4 | 有界自适应 | 按属性跨设备学偏好带，包络内自动，边缘需确认 |
| **L5** | **目标级自主** | 多设备围绕同一目标协商，默认直接执行，人事后可否决 |

## 二、三免与可测判据

| 免除 | 判据 | 当前状态 |
|---|---|---|
| 免确认 | 自动执行占比 ≥ 90% | 待家庭部署实测 |
| 免配置 | 新房间 ≤ 3 个工作日自举到可用 | 待实测 |
| 免调参 | 漂移后 ≤ 7 个工作日恢复基线 | 待实测 |

配套可靠性判据：撤销率 ≤5%、同类错误复发率 ≤1%、安全设备自动调整次数 = 0。

> 这些数字**当前一个都不填**。代码只提供计算口径（`/api/adaptation/health`），
> 没有部署数据就不写结论。

## 三、偏好带（`adaptation/preference.py`）

- 学的是**能力属性**：温度 / 湿度 / 风速 / 开合度 / 目标值，不是设备型号；
- 分桶：`属性 × 房间 × 时段（深夜/上午/下午/晚间）`；
- 取 p20–p80 作为偏好带，样本 < `cold_start_samples`（默认 12）标 `cold_start`，
  **只给区间不给建议**；
- 数据来源：`StateStore.audit_log` 里成功的 set_* 动作，纯函数、可回放。

## 四、目标仲裁（`adaptation/objectives.py`）

多设备争夺同一目标时，用确定性规则裁决：

1. **舒适优先于节能**（`PRIORITY_COMFORT=0` < `PRIORITY_ENERGY=1`）；
2. **可逆优先于不可逆**；
3. **方向冲突只保留一边**：湿度 70% 保除湿、40% 保加湿；空调制冷/制热同理；
4. 同分按 `device_id` 排序，**输入顺序不同、结果相同**（可回放）；
5. 安全设备（门锁/燃气/摄像头/窗户）在仲裁前就被排除。

大模型不参与仲裁——只负责理解自然语言与生成解释。

## 五、四道闸（`execution.check_guards` + `policy`）

| 闸 | 规则 | 配置 |
|---|---|---|
| ① 参数包络 | min/max/enum | `adaptation.json → attributes` + 设备属性 |
| ② 最大步长 | 单次变化 ≤ max_delta | 同上 |
| ③ 最小间隔 | 同设备两次动作间隔 | `min_interval_seconds` |
| ④ 当日预算 | 当日动作总数 ≤ budget | `daily_budget` |

任何一道不过：`gate_ok=False` + 写明原因，提议保留但不执行（不静默丢弃）。

## 六、冷启动（`policy.advance_mode`）

```text
shadow（只计算、不动作）
   └─ 样本 ≥ cold_start_samples → probe（只允许开关类小步长）
         └─ 反馈 ≥ feedback_required → auto（默认直接执行）
```

- 影子模式仍产出提议，`executable=False`，前端可见；
- 探测模式只允许 `turn_on/turn_off`，不做大步长设定；
- 达到反馈门槛才转 auto。

## 七、漂移与降级（`policy.assess_drift`）

24h 滚动指标任一越限：

- 纠正率 > `correction_rate_max`（默认 10%）；
- 舒适带达标率下降 ≥ `comfort_hit_drop_points`（默认 10 点）；
- 感知降级比例 > `degraded_ratio_max`（默认 20%）。

处理：`auto → confirm → suggest_only → off` 逐级退让，**清空反馈、回影子模式重走冷启动**，
连续达标后再逐级回升。

## 八、安全边界

- 门锁、燃气、摄像头、窗户**永不参与任何级别**的自适应；
- 所有动作受四道闸 + 撤销窗口约束；
- L5 的合法性来自"出错能收回"：没有撤销能力，放开确认就是放大错误；
- 照明与窗帘只作演示，主场景是空调、除湿机、热水器、扫地机。

## 九、接口与配置

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/adaptation` | 偏好带、提议、四道闸、等级、冷启动 |
| GET | `/api/adaptation/health` | 纠正率/自动执行占比/降级比例与阈值 |
| POST | `/api/adaptation/tick` | 手动推进一轮（演示） |
| POST | `/api/adaptation/{id}/accept` | 接受建议（走执行入口） |
| POST | `/api/adaptation/{id}/reject` | 否决并写入训练信号 |

配置：`backend/config/adaptation.json`，**默认 `enabled=false`**（不配置就不自动调设备）。

## 十、测试与静态不变量

`python tests_adaptation.py`（28 项）：

- 12 样本非冷启动 / 3 样本冷启动 / 同输入两次一致；
- 湿度 70% 保除湿、40% 保加湿；输入顺序无关；门锁被排除；
- 四道闸逐项拦截；影子/auto 的 executable 差异；
- 冷启动 shadow→probe→auto；漂移 auto→confirm→suggest_only→off；
- L5 动作走 `execution.execute_plan(source="adaptation")`，审计可查；
- `adaptation/` 不含 `registry.control(`（AST）。

## 十一、当前状态（诚实）

- 配置默认关闭，主场景设备是虚拟的；
- 偏好带样本来自审计（会话内），不是真实家庭长期数据；
- 三免判据、撤销率、能耗变化**均待部署实测**；
- 不要对外声称"已实现 L5 自主"——应说"已实现 L5 的决策框架与可测口径，
  真机验证在阶段三"。
